# 设计文档

> 版本：v0.1.0（MVP）｜ 更新：2026-07-24

## 一、产品定位

把 lyzbcy-zeen-tools skill 的能力，从一个"每个项目都要重跑一次、不能 git 上去"的脚本目录，
**固化成一个独立的桌面软件**。用户用一次软件，就能管理所有前端项目，且不往任何项目里写文件。

### 痛点 → 解法

| 痛点 | 解法 |
|------|------|
| 每个项目都要重跑 zeen-tools | 软件统一管理"我的项目"，一键启动 |
| 不能 git 上去、同事用不了 | 软件本身开源到 GitHub，同事装软件即可 |
| token 浪费 | 写死规则识别项目 + 启动，不依赖 AI |

## 二、产品形态

- **mac**：`.app`，release 包内附一键安装脚本（自动解决"已损坏/未签名" Gatekeeper 问题）
- **win**（MVP 不做，设计预留）：`.exe`
- 架构上 main 进程保持跨平台中立，仅外壳/打包分平台

## 三、架构

```
┌─────────────────────────────────────────────────┐
│              Electron 主进程 (main)              │
│                                                  │
│  ┌────────────┐   ┌──────────────────────────┐  │
│  │ 项目存储层  │   │  预览服务器 (内嵌 node)   │  │
│  │ projects.json│  │  PreviewServer 类        │  │
│  │ (~/Library) │   │  - 静态文件 + 路由别名    │  │
│  └────────────┘   │  - SPA fallback          │  │
│                   │  - 目录页注入 (/__nav__)  │  │
│  ┌────────────┐   └──────────────────────────┘  │
│  │ 项目识别器  │   ┌──────────────────────────┐  │
│  │ detector    │   │  生命周期管理            │  │
│  │ (static/fw) │   │  - 端口扫描顺延          │  │
│  └────────────┘   │  - 健康检查轮询           │  │
│                   │  - 进程托管/回收          │  │
│  ┌────────────┐   │  - 浏览器打开            │  │
│  │ IPC 桥      │   └──────────────────────────┘  │
│  └────────────┘                                  │
└─────────────────────┬───────────────────────────┘
                      │ contextBridge IPC
┌─────────────────────┴───────────────────────────┐
│            渲染进程 (renderer, 原生 JS)           │
│   我的项目 / 收藏 / 最近 / 网关端口管理 / 设置    │
└─────────────────────────────────────────────────┘
```

**关键设计原则**：
1. **绝不写用户项目目录**——所有预览能力都在 app 内，以 app 为 server root 之外的临时根启动。
2. **跨平台中立逻辑**——detector、PreviewServer、端口扫描都用纯 node 写，平台差异收口到一层。
3. **写死的规则优先**——项目识别、启动命令用启发式规则，不调 AI，省 token。

## 四、功能设计（MVP 范围）

### 4.1 项目管理（✅ MVP）
- 选择目录 → 添加项目；自动扫描识别类型
- 列表：我的项目 / 收藏 / 最近（打开时间倒序）
- 收藏切换、删除、在 Finder 中打开
- 持久化到 `~/Library/Application Support/本地运行前端项目/projects.json`

### 4.2 一键启动 / 一键关闭（✅ MVP）
- 启动：端口顺延（默认 8091 起，区间扫描空闲）→ 起 server → 健康检查（首页 200）→ 开浏览器
- 关闭：按端口杀进程（SIGTERM → 兜底 SIGKILL）
- 一个项目可同时跑多个实例（不同端口）？MVP：一个项目一个活跃实例，关掉再起。

### 4.3 目录页（✅ MVP，静态项目）
- 扫描项目下所有 `.html`，自动生成目录页，启动后**先开目录页**
- 路由：server 在 `/__nav__` 注入目录页 HTML（不写文件到项目）
- 框架项目（vite/next 等）：走 `npm run dev`，目录页降级为"打开首页"

### 4.4 网关端口管理（✅ MVP）
- 面板列出当前被本软件占用的端口 + 对应项目
- 可手动停掉指定端口的服务
- 启动时自动顺延选空闲端口

### 4.5 更新检查（✅ MVP）
- 打开时拉 GitHub release 最新版本号，与本地比对，不一致弹更新提示

### 4.6 AI-Agent 接入（✅ MVP）
- 提供 prompt 文档 + 一个本地 HTTP 控制 API（`/__ctrl__/*`），agent 可调起启动/关闭/列表

### 4.7 介绍页（⏳ MVP 后）
- GitHub Pages 静态页，带版本号强制刷新逻辑 + 下载按钮 + 推广二维码
- MVP 阶段先占位，v0.2 做

### 4.8 打包成 .app + 安装脚本（⏳ MVP 后）
- 用 electron-builder（或手动打 .app），附去 quarantine 脚本
- MVP 阶段以 `npm start` 跑通为准

## 五、项目类型识别规则（detector）

按"证据强弱"判定，命中即归类：

| 类型 | 判定特征 | 启动方式 |
|------|---------|---------|
| `vite` | 有 `vite.config.{js,ts}` 或 package.json 含 `vite` 依赖 | `npm run dev`（或 `vite`） |
| `next` | `next.config.*` 或依赖含 `next` | `npm run dev` |
| `nuxt` | `nuxt.config.*` 或依赖含 `nuxt` | `npm run dev` |
| `vue-cli` | `vue.config.js` 且无 vite | `npm run serve` |
| `react-scripts` | 依赖含 `react-scripts` | `npm start` |
| `static` | 根目录或子目录有 `.html` | 内嵌静态 server |
| `unknown` | 都不命中 | 让用户手选启动命令 |

mobile-static 也归 `static`，靠 routeAliases 处理 `/m/*`（MVP：自动生成别名见技术方案）。

## 七、技术选型理由

- **Electron**：用户环境有 Node v24，无 Rust（→ 排除 Tauri），无 Xcode（→ 排除原生打包）。Electron 只需 npm，二进制走 npmmirror 镜像（已验证 22s 下载）。渲染层用原生 JS + CSS，零构建，省 token。
- **不写项目目录**：app 以**外部进程**身份把用户项目目录当 server root 启动，全程零侵入。
- **内嵌预览服务器**：直接复用并内联化 zeen-tools 的 `local-preview-server.js` 逻辑（静态文件 + routeAliases + SPA fallback + 目录页注入）。

## 八、不做什么（YAGNI）

- ❌ 多项目并发多实例（MVP 一项目一实例）
- ❌ Windows 打包（设计预留，不实现）
- ❌ token 搬运（qv-admin 那套，属于业务项目特性，MVP 不做）
- ❌ 移动端预览模式切换（mobile-static 的 PC/Mobile 弹窗，MVP 走通用目录页）
- ❌ 复杂的国际化、主题（MVP 单中文 + 浅色）
